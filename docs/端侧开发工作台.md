# 端侧开发工作台

`chongming-device` 提供独立的主视频检测/二维跟踪、辅助视频校准插件入口。
这是算法开发入口，尚未实现参考检测/校准算法，也不把端侧输出自动接入中心端。
完整 `SystemRunner` 不属于此入口的前置条件。

从仓库根目录运行以下命令，即可用默认探针启动：

```sh
uv run chongming-device --scenario scenarios/center_clean.json --output output/device-probe
```

默认启用视频、初始暂停；Godot 和全部声明模块随会话初始化。输出目录必须不存在。
命令包括 `step`、`run [步数]`、`video on|off`、`status`、`reset`、`quit`。
`Ctrl-C` 在当前同步步完成后暂停。`--run` 连续运行到场景有限终点，`--tick-hz`
仅控制墙钟速度；等待、人工暂停、证据写盘不算插件处理耗时。
`--check` 只校验场景，`--no-video` 停止图像生产，仍保留逻辑采样和已启动的插件。
复位创建新的输出目录和新的 image session。

默认 `FrameInspector` 仅用于检查边界：主帧输出 `no_trusted_calibration` 诊断，
不伪造检测、校准解或射线。下游可以先只开发主视频算法；辅助校准成功不应成为
其启动条件。没有可信校准解时，线上射线生成仍必须走诊断路径。

## 接入自己的插件

插件实现 `chongming.ports.development.DeviceAlgorithm`，由受信任的 Python
`module:factory` 显式加载。场景 JSON 不加载 Python 代码。

把以下示例保存为仓库根目录的 `device_plugin.py`，再执行下面的命令。
示例保留默认诊断行为，只记录收到的主帧尺寸，未声称实现检测。

```python
from chongming.contracts.development import DeviceAlgorithmOutput
from chongming.contracts.model import CameraFrame, ProcessingTime
from chongming.device_development import FrameInspector


class MyDevice(FrameInspector):
    def process_main(
        self, frame: CameraFrame, now: ProcessingTime
    ) -> DeviceAlgorithmOutput:
        print(frame.station_id, frame.frame_id, frame.image.width_px, frame.image.height_px)
        return super().process_main(frame, now)


def create() -> MyDevice:
    return MyDevice()
```

```sh
PYTHONPATH=".:src" uv run chongming-device --scenario scenarios/center_clean.json --output output/device-plugin --algorithm device_plugin:create
```

生命周期和输入顺序：

1. `start(DeviceRegistration)` 接收每站 `StationConfig`、本次 image session、
   时钟域和 run ID。配置内的安装姿态是在线估计，不能当作已完成视觉校准。
2. 每个普通 `ScenarioVideoOutput.frames` 按站点与角色派发到 `process_main`
   或 `process_auxiliary`。主辅按各自曝光时间独立采样，主帧不等辅助帧；同一
   采样组先处理主帧，再处理辅助帧。插件应按 station + image session 保存状态。
3. 每个采样组完成帧回调后调用 `tick(DeviceInputStep)`。视频停运时没有帧回调，
   仍调用 tick；不能把无图像解释为成功处理的空目标帧。
4. 有限终点额外发送一次 `stream_ended=True` 的 tick，重复 `step` 不会重发。
   初始化或处理异常会关闭插件、已启动模块和输出文件；`close()` 必须容许部分初始化。

每次回调返回 `DeviceAlgorithmOutput`，包含独立的 detection batches、track states、
calibration updates、station events 和 reason codes。成功处理但没有检测时，应返回
`ProcessingStatus.PROCESSED`、空 observations 的显式 `DetectionBatch`；预测/coast
状态只能放入 tracks，不能伪装成实测射线。端侧工作台不会替插件生成校准结果。

插件只获得普通 `CameraFrame`、在线配置、会话和实验时间，接口中没有生成参数、
真实瞬时姿态、目标真值 ID 或虚拟出口校准解。Python 插件是受信任代码，接口隔离
不等于操作系统沙箱；插件开发时不得主动打开评估真值或场景生成配置。

## 输出证据与验证

`device-registration.json` 保存插件的在线注册输入；`device-input.jsonl` 保存每步
普通帧引用、曝光时间和图像格式，像素单独保存于 `video/` 的 PNG 中。
`device-output.jsonl` 保存逐回调结果、每次 `algorithm_ms`、整步 `device_ms` 和终止标记。
`timing.jsonl` 另存场景阶段耗时；`summary.json` 保存帧计数、终态、关闭健康状态和错误。
`truth.jsonl` 与场景配置属于宿主的独立评估证据，不属于插件输入。

只使用内存 renderer 的入口回归：

```sh
uv run python -m unittest tests.test_device_development -v
```

真实视频验证由完整测试或人工运行执行；Godot runtime 需要串行运行，不能同时启动
多个开发工作台或预览。首轮可从 `center_clean.json` 开工；射线误差和抖动实验的
适用边界见 [场景说明](../scenarios/README.md)。
